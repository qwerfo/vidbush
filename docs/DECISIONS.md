# Decisions

One line each: the decision and why.

- Sandbox blocks Wikipedia, YouTube, Archive, LoC, NASA, OpenAI-style APIs and ElevenLabs. All adapters are built and tested against canned responses; the demo runs in mock mode with a bundled local footage library.
- Added a `local` candidate source (operator footage library folder with sidecar tags). It doubles as the offline fixture source and is useful for owned stock.
- Installed espeak-ng so mock narration is intelligible speech, not tones. Tone bursts remain the last fallback.
- Bundled Inter (OFL) as the one font family, and Natural Earth 110m and 50m countries, 50m lakes and rivers, and a 7342-place gazetteer from Natural Earth 10m populated places for offline maps and geocoding.
- Python 3.13 is what the sandbox has; code targets 3.11+.
- Every LLM caller has a deterministic heuristic fallback, so mock mode works for any input, not only the demo fixtures.
- Director works in two layers: per-beat visual ideas (LLM or heuristic), then a deterministic pacing engine assigns typed, timed slots. This keeps the visual mix and pacing exact regardless of model quality.
- Captions are burned per segment (window of the global caption list) so the segment cache key includes the caption slice, as the spec requires.
- Transitions are hard cuts plus a short fade through black at some scene starts, rendered inside the segment, so segments can be concatenated with stream copy and cached independently.
- Built-in Python motion graphics renderer is the default (about 30 to 60 fps at 1080p, maps pre-render static layers). The Remotion project in renderer/ renders the same MotionSpec and is selectable with render.renderer: remotion; it falls back to Python on any failure.
- Visual mix percentages are measured by shot count (QA also reports screen time share), because motion graphics are longer than footage and a time-based mix would starve footage.
- Music bed level: bed_gain_db is the level under speech relative to the -14 LUFS target; the bed rises by ducking_depth_db in pauses of 0.8 s or more. The ducking key is a smoothed, gap-merged speech envelope, so the bed holds one level through sentences with no per-word pumping.
- Loudness uses ebur128 measurement plus a linear gain and a true peak limiter only when needed (same target as two-pass loudnorm linear mode, faster, verified after the pass).
- Chunk stitching in narration uses a sample-exact numpy 40 ms linear crossfade so word timings shift exactly.
- The director guarantees one data chart per video whenever any beat has two or more comparable numbers, and parses spelled-out numbers ("one hundred dollars").
- Docker image is based on ubuntu:24.04 (Python 3.12, FFmpeg 6, espeak-ng from the Ubuntu archive).
- Built UI (ui/dist) is committed so Windows and Docker users do not need Node to run Vidbush.

## Footage quality and YouTube (parallel lane)

- Footage quality work (parallel1) is developed on the session branch claude/footage-quality-youtube-3eojov and the same commits are pushed to footage-quality, the branch name Adam asked for.
- Prefilter OCR uses rapidocr-onnxruntime 1.2.3: its three onnx models (det, cls, rec) ship inside the wheel, verified by installing and listing the package files, so nothing downloads at runtime.
- Prefilter face check uses the OpenCV haar cascades. mediapipe 1.2.2 (the current wheel) was installed and checked: it has no solutions module and no bundled face model (the tasks API downloads a .tflite), so it was rejected. opencv-python-headless 5.0 no longer ships cv2.data haar files; 4.14.0.94 does (verified), so OpenCV is pinned to 4.14.0.94, with opencv-python at the same version because rapidocr requires it.
- Every new threshold lives in config (judge.prefilter, judge.*_detail, sources.youtube_*, cost.vision_per_image_high_usd) and the brand gets licence_policy.prefer_creative_commons; all new config fields were added in one commit first so the four parts could be built in parallel without config conflicts.
- Prefilter: one entry point (_prefilter_and_score) before every vision call in the director loop (first pass, requery, AI retries). A reject gets score 0 and reject_reason "<label> (prefilter: detail)", which selection already treats as a hard reject.
- Prefilter skips operator and generated media (local library, uploads, AI stills and clips, motion graphics); logo and face checks run on video only, since a still has no temporal evidence and a still portrait is a normal documentary subject.
- Subtitle rule: OCR boxes below text_band_top are grouped into rows, then into runs of horizontally close boxes (gap at most 1.5 text heights); only a run at least text_min_width wide counts, so corner bugs and timestamps on one row never merge into a subtitle.
- Logo rule: a textured, pixel-stable blob inside a corner box, not touching the sides facing the centre, with changing pixels around it; static clips (75 percent of the centre stable), letterbox bars, flat skies and dark corners never count.
- Face rule: haar frontal cascade with minSize derived from face_min_area, so crowds and small faces are never searched; profiles pass because the frontal cascade does not fire on them.
- A prefilter dependency that fails to load (import or model build) disables only its check, with one warning per process.
- YouTube licence policy reaches the adapter as optional search hints declared by the adapter, so the adapter interface and other sources are unchanged. The CC pass uses sp=EgIwAQ%3D%3D (checked against the installed yt-dlp YoutubeSearchURLIE), is capped at 10 items, and a failed CC pass never drops the normal pass.
- standard_youtube_licence is a flag on the candidate and shot, counted in QAReport.standard_youtube_assets and its own qa_report.md section. Flag only, never a block.
- YouTube windows: with captions or chapters, the window (shot x4, 30 to 75 s, stepped by half a window) with the best token overlap wins (must_show weight 2, intent 1, queries 0.5); else up to youtube_windows windows of 15 to 30 s at even fractions between 5 and 95 percent. Each window is its own cached download with 10 s padding, and at most 4 clips per video in total.
- Window files are named youtube_<id>_<true start seconds>; the true start subtracts the keyframe lead measured from the probed file duration, because stream-copied section downloads begin at the keyframe before the requested start. Re-encoding at cuts was rejected as too slow.
- yt-dlp gets a private temporary copy of the cookie file per call, because yt-dlp rewrites its cookie file in place on close and parallel downloads would corrupt it; the operator's cookies.txt is never modified.
- Downloads of different videos run in parallel up to youtube_download_workers with a per-URL lock; searches, info extraction and caption fetches stay on the serial 0.5 per second slot. Search usage per run goes to work/source_notes.json so qa_report shows "YouTube searches used: X of N" and a warning when a budget ran out, across resume.
- Segment dedupe: same segment means same asset, video media, and ranges that overlap or start within 3 s on the source timeline. It is banned within a scene and for adjacent non motion graphic shots (a graphic between two shots does not reset adjacency); in another scene it costs 40 points. The ban is applied before the threshold split: an allowed below-threshold candidate or a fresh AI still beats a banned repeat, and a forced repeat is flagged segment_repeat and no_match_accepted.
- Editor re-sourcing of one shot runs enforce_segment_rule against its neighbours and scene, and in-point variation of repeated video skips starts that would recreate a banned segment.
- Judge detail is a per image list on Seats.vision_json defaulting to low, so only the judge pays for high detail; auto is priced as high in the missing-cost estimate. All vision images are downscaled to fit 640 px before sending so the flat per image prices hold for full-size AI stills too.
- vision_per_image_high_usd default is 0.010 (5x low): a 640x360 frame at high detail is 2 tiles, 85 + 170 x 2 = 425 tokens against 85 at low.
- max_tokens is read from provider or role options in seats.yaml and never sent unless set to a positive int; a 400 pointing at max_completion_tokens teaches a rename quirk. The SPEC line now says no cap by default.
- LLM timeouts resolve per role (writer 600 s, others 180 s); a caller asking for longer wins, and options.timeout_s replaces the role default outright.
- A reply with finish_reason length or max_tokens is continued once (partial as an assistant message plus a continue prompt, no response_format); a second truncation or unparseable joined JSON raises RefusalError, which fails over to the next provider without marking the first one down. Usage of both calls is summed.

## Visual mix, director context and batch queue (parallel lane)

- Visual mix: animation is split into `full_screen_cards` and `animated_overlays` keys inside `visual_mix`. Overlays are counted on top of the shot they decorate, so they are added to footage_overlay and image_overlay in the picture's footage to still ratio (41 to 17). The documentary default becomes footage 20, footage_overlay 42.2, image 7, image_overlay 18.8, motion_graphic 12: the reference's raw shares stay exact and the total stays 100.
- Old profiles that use the `motion_graphic` key read it as `full_screen_cards`, so learned and older profiles keep working. The learner now writes `full_screen_cards` with `animated_overlays` 0, because a classifier already counts the overlays it sees as overlay shots.
- The top10 profile uses 20 full screen cards and 22 overlays (42 in total). Its number cards are full screen by design and are always kept.
- The 45 s card spacing is enforced twice: as a planner penalty, and in a final `space_cards` pass after the chart guarantee. Structural cards (number cards, title card, recap) are never removed and count against free cards near them. When the cap and the mix disagree, the cap wins.
- A map or chart used as an overlay renders as an inset panel (45 percent of the frame width, upper right, larger type). Insets always use the Python renderer, even when Remotion is configured, because Remotion has no inset composition.
- A free map or chart card removed by the spacing cap keeps its content as an inset on footage of its beat, so the information stays on screen.
- An inset map is offered only when it shows a place that no map showed in the last 60 s. Without that limit the Panama scripts put a map on about 20 of 70 shots.
- Insets are kept at least 15 s apart, and the same map or chart is not shown again within 3 minutes. An inset is information the viewer has to read, and the first demo render put one on 43 percent of shots, back to back in the opening.
- MG_RENDER_VERSION is now mg-3, because chart value labels now always fit inside the plot and cached charts must re-render.
- Acceptance adds three checks: cards_sparing (full screen cards at most 25 percent of shots), overlays_on_picture, and inset_map_or_chart.
- Director chunks now run one after another instead of four in parallel, because each call needs the ideas chosen before it. This costs wall time on long scripts: about one call per 8 beats, in sequence.
- The script summary comes from the director seat (task `script_summary`). It is cached in work/script_summary.json, keyed by a hash of the script, so a re-run of the shot list does not pay for it again. Its fallback is the title plus the first sentence of every scene.
- The visual anchors so far are the research anchors that the chosen ideas mention. Script and voiceover projects have no research, so they get the recent must_show subjects instead.
- The director may now propose map and chart overlays. These get the same coordinate and fact checks as motion ideas and render as insets. An inset map must draw a marker, a route or an arrow.
- Heuristic fallback notes are recorded through `seats.note_fallback`, and only when the role has a configured real provider, because mock mode is already reported as mock. Each stage writes its notes to work/fallbacks.json and replaces its own earlier entries, so a re-run that succeeds clears them.
- A director chunk counts as a fallback when the call fails or returns no valid idea. The script summary fallback is reported with scene id "all". A writer section counts when its beats come from fact claims.
- Batch cost cap is checked after each stage against the project's cost_report total (which includes earlier runs), so a run stops at the next stage boundary, never mid stage; stopping inside a stage would leave half written outputs.
- A capped project ends as needs_review with project.status_note and work/cost_cap.json; the batch shows it as capped. No new project status value, so the UI, API and final status logic stay unchanged.
- No cap check after the last stage: the video is finished by then, so stopping saves nothing.
- A batch runs as one worker job (kind batch, project_id batch:<id>) that runs its projects in sequence through jobs_handler.run_pipeline, so batches reuse the job table's crash recovery and the API worker's exact pipeline path.
- Batch pause is a flag in state.json read between projects; the running project always finishes. A per-item resume uses the existing stage resume, so an interrupted batch never recreates a project it already started.
- Batch project ids come from file stems like run (unique suffix _2, _3 within a batch) and replace an existing project of the same id, matching run.
- Batch CLI uses flat names (batch, batch-status, batch-pause, batch-resume) so `batch <folder>` stays a single positional command.

## Review sheet (parallel2, branch review-page)

- The review lives in output/<id>/review.json, one entry per shot in shot list order plus the project comment. Unreviewed shots are entries with verdict null, so the file always has one object per shot.
- Comments have no length limit anywhere: no max_length in the pydantic models or the API bodies, no maxlength on the textareas, and the export quotes every line. This is Adam's standing rule for review sheets.
- Each shot entry stores a snapshot of the shot (type, intent, pick, site, licence, judge score and reasons, rejected candidates) taken at its last change, so the export and the calibration describe the pick Adam actually saw even after Apply fixes re-sources the shot.
- A shot that leaves the shot list (merge, split) keeps its entry with in_shotlist false and is not counted in "Reviewed: n of m".
- "Reviewed" means a verdict is set. Ticking rejects or typing a comment alone does not count.
- The hard reject checklist maps onto judge labels for calibration: burned-in text to burned_in_captions, watermark or logo to watermark and channel_logo, talking head, anachronism, repeated clip to the segment_repeat flag.
- Export replaces em dashes inside comments with a comma pause (no_em_dash); review.json keeps Adam's text verbatim.
- review.md also lists shots marked not good without a comment, in a table, so an AI reading it cold sees every problem, not only the commented ones.
- The re-source fix uses the existing change_type path (_resource) with three new optional args: add_must_avoid, add_queries, reject_selected. No new EditOp name, so the chat editor, CLI op and edit log keep one vocabulary.
- reject_selected marks the reviewed pick rejected (score 0) before re-sourcing; without it the judge would usually pick the same candidate again.
- When must_avoid grows, every unrejected candidate loses its score so the judge rescores it against the new must_avoid. This costs a few vision calls for one shot and is the only way the new avoid note can change the pick.
- The comment goes to must_avoid in full. Only the part that says what Adam wants (after want, need, show, use, instead, prefer; negations cut off; at most 12 words) goes to queries. The literal spec said the comment goes to queries too, but the audit showed a complaint such as "this is generic harbour footage" then searches for the very picture he rejected, so a comment with no want phrase adds no query.
- Wrong picture on an AI image maps to regenerate_ai with "Avoid: <comment>" (cut to 300 characters for the image prompt). On an AI video or a motion graphic it stays a comment: regenerate_ai would turn a video into a still, and a graphic has no safe automatic edit.
- Quality problem maps to a re-source only when a hard reject is ticked, with that reject's plain words added to must_avoid. Without a tick it stays a comment.
- Wrong timing produces no op. The plan lists those shots with an "Open duration editor" link to #/p/<id>/<shot_id>, which opens the existing shot panel with the duration box focused.
- Apply fixes records the queued op on each shot entry. A shot is planned again only when its verdict or rejects change after that (a comment edit alone may be a typo fix on the old review), or when the fix job failed or its edit plan lists an error for the shot. The CLI marks only the ops that applied.
- After a fix, a comment edit keeps the old snapshot, so the export and calibration never pin the old verdict on a pick Adam has not seen. Setting the verdict again reviews the new pick; the row says so.
- Calibration reads only structured labels on the pick (its reject labels and flags) to decide whether the judge caught a ticked reject. Free text reasons also say things like "no watermark visible".
- A review entry is matched to a shot by id, beat, pick and length. When a shot leaves the list its entry is kept with in_shotlist false (saved on the next load); if a later split reuses that id for a different piece, the old entry is archived as <id>~<time> and the new piece starts unreviewed.
- Export numbers and times come from the snapshot, so they describe the render Adam reviewed even after edits renumbered the shots.
- Apply posts exactly the ops shown in the preview (like the chat panel) to POST /review/fixes, which enqueues one apply_ops job.
- Calibration counts only picture verdicts: good against wrong picture and quality problem. Wrong timing and other say nothing about the judge. Shots without a judge score are skipped.
- Suggested threshold: the whole number 0 to 100 with the fewest disagreements; ties go to the value closest to the current threshold, then to the stricter one. Simple, explainable and stable on small samples.
- A ticked reject counts as missed by the judge when the reviewed pick's reject reason, judge reason, notes and flags carry none of its equivalent labels. Each missed reject names the prefilter setting to tune.
- Every Review page action is a CLI subcommand too: review-set, review-comment, review-export, review-summary, review-fixes (with --apply) and review-calibrate.
- The review page docks the player in the lower right corner once it scrolls out of view, so the video stays visible while reviewing row 80 of 100. The same video element moves, so playback never restarts.
- Arrow keys move between shots and seek the player to the shot start; number keys 1 to 5 toggle the verdict; Space plays or pauses; c focuses the comment; Esc leaves a text box.
- Comment autosave is debounced 600 ms and flushed on blur, before export, before Apply fixes and on page leave. Saves for one shot run in order so a slow request never overwrites newer text.
- The demo render for the screenshot ran with --offline: the default config reached YouTube from this sandbox, and the brief allows no network beyond GitHub and package registries.

## TTS seats, Anthropic provider, streaming, seat policy, source budgets (parallel1, branch tts-seats)

- Algrow TTS is its own provider type algrow_tts in vidbush/providers/tts_algrow.py, ported from RadioPlay's gateway/adapters/algrow_tts.py (submit, poll, download), because an async job API does not fit the ElevenLabs request shape.
- TTS adapters register in one dict in seats.py (TTS_TYPES, one line per type), so the laptop lane's elevate_tts adds one line and the two branches merge without touching the same lines.
- A tts entry whose type is not registered is skipped with one warning per process, because a seat list may name a type another branch is still adding and a run must not fail for it.
- Algrow is a subscription: calls are recorded as 0 USD and the reported credit count goes into a new optional CostEntry.credits field, so spend stays visible without inventing a dollar price.
- Short Algrow scripts are padded with break tags to its 200 character floor, as RadioPlay does, because Algrow answers HTTP 400 below it; Vidbush chunks are whole scenes, so this only touches tiny scenes and single beat re-narrations.
- Voice ids live per provider in brand voice.voice_ids (name, then type) with voice.voice_id as the one default, because the same voice has different ids on different TTS services.
- Alignment routing: a TTS chunk without usable timings (none returned, drifting, mock, or a seat with force_align: true) is aligned against the script with the Aligner that narration_from_voiceover uses, inside the chunk's exact stitched window rather than across the whole file, because the window offsets are known exactly and only narrow the search.
- force_align is a tts provider option read through Seats.tts_option, because unreliable timings are a property of one provider, not of a brand or a run.
- The first narration chunk is synthesized alone before the rest run in parallel, so a refused model switches the run (sticky in each adapter) before any other chunk exists and a video never mixes models.
- A narration whose chunks came from more than one tts provider is logged as a warning, not redone: redoing would ask the same failing seat order again.
- The native Anthropic adapter speaks the Messages API over the repo's own requests layer, not the anthropic SDK, because every provider shares one retry, 429, fallback and cost path in ProviderClient, and the SDK's own retries and exception classes would duplicate and bypass it.
- The Anthropic adapter never sends temperature (current Claude models reject sampling parameters with a 400); options.send_temperature exists for older models.
- max_tokens is sent on every Anthropic call (64000 streamed, 16000 not, or options.max_tokens) because the Messages API requires it; a 400 naming a lower limit teaches that limit for the model.
- Anthropic JSON is asked for in the system prompt and read with the shared loose parser, because the Messages API has no json_object mode and structured outputs would tie every caller to a schema.
- The Anthropic price table is built in (USD per million, cache reads and 5 minute writes at their own rates) with options.price_per_mtok as the override, because the direct API returns no cost and has no price list endpoint.
- LLM and TTS type registries map a type to its module and look the function up at call time, so a test or a hot fix that replaces llm.chat still takes effect.
- Streaming is the default for every openai_compat provider (options.stream: false turns it off per provider), on Adam's rule that Wellflow and CloseRouter calls are faster and stop timing out when streamed.
- A relay that rejects stream_options teaches a quirk and is streamed again without the usage request, so a strict relay does not lose streaming; its cost then comes from the price list or the estimate.
- A streamed request answered with plain JSON is accepted as that JSON, because some relays ignore stream and a whole reply is still a whole reply.
- Seat policy (Adam, 2026-11-05) lives in config/seats.yaml: Sonnet 5.5 for director and researcher and Opus 5.5 for writer on wellflow_cheap, anthropic_direct as the alternative primary, CloseRouter's Anthropic ids as the fallback; editor, judge, vision and cheap_classifier on CloseRouter then the normal Wellflow key; tts elevate_tts, algrow_tts, elevenlabs; images unchanged.
- CloseRouter is the third Anthropic seat because RadioPlay's standing order (item 961) is Wellflow first and CloseRouter when Wellflow is down, and a Wellflow outage must not stop a script.
- Anthropic seats name model_match {family, version} and the id is read from the provider's GET /models once per provider and logged once, because each relay spells the same model differently and a guessed id only fails on the first billed call. model_env still pins an exact id when set.
- A failed model listing is not cached (retried after 10 minutes like a down provider), so a relay that is down at startup does not lose its seat for the whole process.
- The temporary primary is an .env switch (VIDBUSH_PREFER_PROVIDER plus VIDBUSH_PREFER_UNTIL) that ends by itself, so Adam's 48 hours on anthropic_direct from 2026-11-05 need no config edit to undo.
- New env names (WELLFLOW_CHEAP, WELLFLOW_API_KEY, CLOSEROUTER_API_KEY, ANTHROPIC_DIRECT_API_KEY, ALGROW_API_KEY, ELEVATE_API_KEY) name the provider, not the role, because one key now serves several roles; the old LLM_PRIMARY_* and VISION_* base URL and key variables are no longer read.
- Provider unit tests load tests/fixtures/seats_generic.yaml (the old generic layout) instead of config/seats.yaml, so a change of operator policy never breaks a test of a mechanism.
- Source budgets are shared fairly: every shot that still needs candidates is in each adapter's pool, may spend the pool split evenly (the remainder one each to the first shots in timeline order, so no search is left unused by rounding), and leaves the pool once its web results fill a plan, returning its unused share. Reason: live run 1 spent the 150 Pexels searches in the first shots and later shots got none.
- Sourcing queries now go out in rounds (every shot's first query, then the second for shots still short, then the third) instead of all at once, because a share can only be returned after the round that showed the shot has enough.
- "Enough" counts web results only (not the local library), so owned footage never stops a shot from also searching stock sources, matching the earlier behaviour for local libraries.
- A re-query of one shot (director loop, editor) rejoins the pool with its earlier spend counted and leaves it afterwards, so late re-queries draw on what the run left over.
- qa_report shows a usage line for every source with a run budget (not only YouTube), with the number of shots that shared it and the searches deferred by fair shares.

## Run 2: Provider seats, env loading, TTS

- Settings read .env, then .env.local, then the process environment (each later one wins), because Adam keeps every new seat key in .env.local and run 2 would otherwise have used mock for every text role; tests still read neither file.
- The seat lists in config/seats.yaml state Adam's 2026-11-11 policy in its exact order: writer wellflow_cheap, closerouter, anthropic_direct; director and researcher closerouter, openlux, anthropic_direct; editor closerouter, openlux, wellflow; judge, vision and cheap_classifier closerouter, openlux, wellflow; tts elevenlabs, elevate_tts, algrow_tts; images unchanged.
- Exact ids are written where they are verified and model_match is used only where a relay's spelling is unknown (CloseRouter Sonnet 5.5, openlux and Wellflow Grok, openlux Gemini), so no seat sends a guessed id.

## Run 2: Text overlays

- An overlay belongs to a spoken moment, not to a shot: MotionSpec gains `anchor` (the narration words) and `start_at` (seconds into the shot), so render and segment caches invalidate when either changes. Run 1 put every overlay at its shot start, 3.4 s from its words on average and up to 9 s early.
- The anchor is the seat's `anchor` field, else the overlay title. Matching uses normalised tokens (spelled numbers as digits): the run holding the most of the anchor's content words (at least half) within its length plus two words, earliest on a tie.
- A text overlay appears 0.2 s after its anchor's first word starts, never before it, and holds max(1.5 s, 0.3 s per word) before the cut. A shot that misses that moment hands the overlay to the nearest plain shot within 12 s that holds it (no run of three same types), else the overlay is dropped and the shot is plain.
- Timing runs once in the director after the rules (rules.time_overlays), because merges, swaps and card spacing all move shots; overlay_pool and dedupe use the same fit test so a shot is offered overlays whose words it holds.
- overlay_pool also offers the overlays of every idea of the shot's beat and its two neighbours, best idea first, so a seat overlay whose own idea became a card still reaches the picture.
- Map and chart insets and locked structural overlays (Top 10 item lower thirds) keep start 0: they label a picture or an item, not a word.
- The renderer renders a timed overlay for duration minus start_at and the segment delays it with setpts (+start_at/TB); the overlay filter passes the picture through before the first overlay frame, so the text animates in at its moment.
- The editor keeps an anchored overlay on its timeline moment when shots are resized, split, merged or moved (narration does not move): it stays on the shot whose [start, end minus reading time] holds the moment, else moves to the plain shot that does, else is dropped (a clamp into the shot showed it before its words or far from them). A rewritten beat shifts the moments after it with the narration.
- repeats_narration(text, narration): 4 or more consecutive normalised tokens, or 60 percent or more of the content words, spoken in the beat (seat) or within 8 s (director and QA). Names of 3 tokens or fewer are exempt (a lower third, or text whose every word is capitalised, a number or a stop word), so names, places and years pass; other short text repeats when all its tokens are spoken in a row, so a short clause of the narration (Diphtheria hits Nome) is caught.
- The heuristic key-phrase callout (overlay_options), the default_overlay fallback, and the heuristic quote and callout cards (text_ideas) are deleted: they were the beat's own words by construction (27 of 33 run 1 overlays, 82 percent). A heuristic cannot paraphrase, so it keeps only years, named lower thirds and noun labels.
- A seat overlay that repeats its beat is cleared and a seat quote or callout card that does is rejected; nothing replaces them with narration words.
- The director seat prompt asks for overlay text that adds a fact (number, date, place or role label, unit conversion, source) or paraphrases in 2 to 6 words, plus the anchor words, with the reason (captions already show the narration) and "no overlay" as the answer when nothing can be added.
- Overlay shares in the mix are a ceiling, not a quota: an overlay slot with no honest overlay is plain footage. A motion slot whose best card was already shown, or whose beat has nothing to draw, takes footage instead of a repeated card (before, verbatim quote cards filled those slots).
- qa_report records overlay_text: text items, median absolute gap between a text overlay's first frame and its anchor word, unanchored overlays, and the share of on-screen text (overlays and quote or callout cards) that repeats the narration. Notes warn above 0 percent verbatim or 0.5 s median gap.
- QA mix notes treat footage_overlay and image_overlay as ceilings and compare footage and image with their overlay siblings combined, so plain shots taking honest-less overlay slots no longer read as a mix miss.
- Acceptance overlays_on_picture now means some animation rides on the picture and every on-screen text is honest and on time (0 percent verbatim, median gap at most 0.5 s, none unanchored); the old rule (overlay shots at least the card share) counted verbatim callouts as success.
- Tokens drop a possessive 's and split hyphens (Nenana's is nenana, dog-sled is dog sled), and anchor_time matches each narration word by its own tokens, so a name said in possessive or hyphenated form still anchors its overlay.
- QA measures a text overlay against the word the pipeline anchored it to (its shot, before it shows, the overlay_start window) and only falls back to the 8 s window when that finds nothing, so a name also said a few seconds earlier no longer reads as a large timing error.
- Editor overlays follow the director's rule: set_overlay times a text overlay to its anchor inside the shot and rejects it when the shot does not hold its words or the text repeats the narration; a rewritten beat re-times its own shots' overlays to the new words and clears those that no longer fit.
- The editor never makes on-screen text from the beat's narration: a text card without text takes the shot subject, and a revise request to add text without quoted words takes the shot intent (the headline fallbacks are deleted).
- Free callout and text cards are checked against the narration spoken within 8 s (demote_repeating_cards, after space_cards), the same window QA and acceptance use, not only their own beat; a card that repeats becomes footage.

## Run 2: Map and route motion graphics

- A route line is drawn only from real geometry between two places the gazetteer resolves; model coordinates (route points, marker lat/lon, arrows) are never rendered. Run 1 drew three invented points labelled with the next beat's distance (Hurricane Turn, shot_031).
- The director names places, not coordinates: a marker is {place, label} and a route is {from_place, to_place, via, label}. MapRoute gains from_place, to_place and via; points are filled by the code.
- via is road, rail, river, sea, trail, air or line. When the director gives none it is inferred from the route label, then the map title, then the idea intent, then the beat narration, and falls back to line.
- Bundled Natural Earth 10m railroads and roads and 50m admin_1 states and provinces (public domain), stripped to scalerank (lines) or name, admin, adm0_a3, latitude, longitude (admin_1), simplified (rail 0.002 deg, roads 0.004 deg, admin_1 0.002 deg) and quantized to 3 decimals, lines grouped into one MultiLineString per scalerank. Total 13.3 MB, under the 15 MB limit, so no download script; road ferries are left out.

- A rail, road or river route that cannot snap, or whose snaps are not connected, is dropped and the map keeps the endpoint markers. Trails have no bundled data and are never drawn. Sea and air routes are a dashed great circle that claims no ground path.
- A river route is the real river centerline between the endpoints' snaps, over the same graph code as rail and road.
- The renderer draws a traced route (via set) exactly as its geometry; only legacy point lists without via are still smoothed.
- Traced paths are thinned to at most 300 points in the payload. Simplified layers measure up to about 5 percent short of published lengths, inside the 25 percent tolerance.
- A distance label is computed from the drawn geometry. A distance the model wrote (route label, title or marker label, digits or words, miles or km) only confirms it: more than 25 percent off drops that text, and a confirmed text keeps its number.
- A distance in a title or marker label is checked against the one drawn route, else the separation of exactly two markers, else dropped (run 1 put '70 miles apart' on a 1034 mile line).
- Markers and labels are gazetteer places. A marker outside the director's own view is sign-checked (a homonym of the same name inside the view, or a view written with a flipped latitude or longitude sign, which refits the view) and otherwise dropped.
- The view is kept when it holds every marker, route point and shaded region middle inside the safe band at the deepest zoom; otherwise it is refitted with map_view. A shaded region alone is framed whole.
- A map with no marker, route or real shaded region left is rejected (validate_idea returns None), so the slot falls back to footage. An inset still needs a marker or a route.
- Shaded regions must exist in admin_0 or admin_1 and are stored under their canonical name; others are removed. The renderer shades admin_1 names too, so states such as Alaska, Texas and Hawaii are now shaded (run 1 drew nothing for them). Island groups such as the Aleutians are in neither layer and are removed.
- Only major rivers (scalerank 6 or less) are drawn, at every zoom, each with a small name label, so a minor river never reads as an unexplained route.
- State and province borders are drawn faintly from zoom 3.5, and faint roads and railways from zoom 5 (scalerank 6 or less below zoom 7, all above).
- A map's source_note is always "Map data: Natural Earth", never model text.
- One verify_map in shots/seat.py replaces fix_map and is called from both seat paths (motion idea and overlay inset) and from the editor's motion_spec path, so every model-written map gets the same check.

- Not done this round: no gazetteer extension, so small places missing from NE 10m populated places (Hurricane, Coldfoot, Deadhorse, Toksook Bay) are dropped rather than drawn; a GNIS subset would add them.

- Before giving up on a panel, sizes of 85 and 72 percent are tried while the content still fits at the type floors.
- A subject that runs across the frame (a train) may be overlapped at its edge; only its heart (the blob's box shrunk to 60 percent around its centre of mass) is protected, and the strongest centre-weighted blob is the subject.
- Place chips forced into a crowded map stay inside the frame on the least crowded side, because a chip cut by a panel edge read as broken.
- Document focus takes a purpose (evidence, period, subject) and the panel presentations, because a whole page filling the screen with nothing happening is what weak editors do (Adam).
- Evidence: the page is seen whole for about 1.4 s, then the camera moves to each passage, the rest dims, and the passage is marked as it is read; a source label is always shown.
- Period: no marks and no claim about the page's text, a slow push toward its masthead; usually a panel over footage.
- Subject: full frame, the camera visits each named part in spoken order and marks it there.
- Mark form follows the passage: underline up to about four words in running text, highlighter sweep over one or two lines, highlight block for longer, a drawn ring for a figure, a date, a signature or a label standing alone; marks sit on the OCR quads and follow the page's skew; each starts on its own first word and travels at reading pace; earlier marks stay, quieter.
- A document panel is sized so its key phrase reads at the 34 px floor; a page that cannot be read at a sane panel size is shown for its look only, with no marks.
- Full documents may hold up to 14 s, because a page read in two or three marked passages needs longer than a card.
- No Alaska evidence example uses real narration: an OCR survey of all 168 archival stills in the run 3 pool found no page carrying words the narration says, so evidence is proven on invented narration only and no quote is paired with a page that does not carry it.
